Built to be looked at, and looked through.

File Studio started from a simple annoyance: to rotate one page of a PDF, most of the web wants you to upload the whole document to a stranger.

The idea

Browsers have been able to read, render and rewrite files on their own for years. So every tool here does exactly that — the work happens where the file already is. No queue, no “processing…”, no promise to delete it later.

How it's put together

  • A static site: HTML, one stylesheet, one helpers file. No build step, no framework.
  • One page per tool, so each page loads only what its job needs.
  • Open-source libraries do the heavy lifting: pdf-lib, pdf.js, Tesseract.js, SheetJS, mammoth, JSZip, PptxGenJS, html2canvas, marked, qrcodejs.
  • The background object on the home page is drawn from scratch — an icosphere generated in code, rotated and projected onto a 2D canvas every frame.

What it's honest about

In-browser conversion has real limits, and the tools say so where it matters. Recognising text from a photo is a guess, not a transcription. A PDF rebuilt as Word or PowerPoint keeps your content, not the original typesetting. Spreadsheet detection inside a PDF works on clean tables and struggles with messy ones. Every tool that approximates something tells you before you rely on it.

Running it yourself

Open index.html in a browser, or serve the folder with any static file server. There is nothing else to configure.
